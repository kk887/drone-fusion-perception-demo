## 一、怎么运行

**方式 A：直接双击 `index.html`**（无需任何环境，纯静态、可离线）

**方式 B：本地起服务**（推荐，路由/缓存行为与正式部署一致）

```bash
node serve.js
```

然后打开 http://localhost:8899 。

> 无需 npm install。ECharts 已本地化到 `assets/js/vendor/`，全程不依赖外网。

## 三、这个 Demo 和原型稿的关键差别

### 1）单一数据源（最重要）

原型稿各页面数字是分别编的，出现了 `1,248` 同时当作"今日目标数 / 近30天飞行总次数 / 设备总数 / 处罚总数"这类矛盾。

本 Demo 所有页面的指标 **全部从 `assets/js/mock.js` 的同一份数据集聚合派生**，页面里没有任何硬编码统计数字。

点击右上角 **「数据一致性自检」**，可实时校验 21 条跨页面口径断言（区域分布合计 = 总数、日趋势累加 = 总数、案件可追溯到非法目标……）。这也是纪要 §8.2 "页面每个字段必须有来源"的落地方式。

### 2）已修正的原型稿逻辑问题

| 原型稿问题 | 本 Demo 的处理 |
|---|---|
| `1,248` / `326` 等数字跨口径复用 | 各指标独立派生，自检断言守护 |
| 首页 TDOA 卡「总数 108 = 在线 98 + 离线 8」不成立 | 强制 总数 = 在线 + 离线 + 异常 |

### 3）业务合规改造

纪要 §6.3 / §11.1 要求"反制与公安信号干扰必须保留人工授权、目标确认、范围校验、停止/急停、回执和全过程审计"。Demo 中：

- 融合感知中心「发起联动反制」→ 四段式授权确认，未勾选双确认无法下发；
- 执行监视窗口有 **停止 / 急停** 按钮，并逐条打印实际会调用的接口；
- 处置处罚管理有独立的 **反制与公安信号干扰授权记录** 表（授权编号、审批人、操作人、设备、频段、作用范围、时长、回执、急停、审计完整性）；
- 「发起公安授权信号干扰」需填审批编号并勾选三项确认。

### 问题定性

用户指出「授权记录表格第一行没顶格」「反制与公安信号干扰授权记录放在这个页面布局有问题」「归档趋势统计、归档类型分布也是这样」。实测定位到同一根因：**内容与容器尺寸严重错配**。

以授权记录表为例：15 列 × 26 行（内容 1569 × 1039px）被塞进底部 **115px 高、1/3 宽**的面板，既要横滚 1569px 又只能看 2 行 —— 粘性表头与首行被挤压，视觉上就是「没顶格 / 表头被切一半」。

### 处理

**1）信息架构：两个页面改为页签制**

| 页面 | 改造 |
|---|---|
| 处置处罚管理 | 拆为「处罚案件管理」/「反制与干扰授权审计」两个页签。授权审计页签为全宽布局：授权概览 + 处置结果分布 + 授权类型与联动单位 + 全宽审计表。**可视区从 115px×0 变为 430px×1378px，横滚完全消除** |
| 日志归档 | 拆为「日志检索」/「归档统计与策略」两个页签。检索页签列表可视高 465px；统计页签趋势图高度 **128px → 476px** |

页签切换按需渲染并重新初始化图表，切换后工具栏按钮仍可用（原直接绑定改为按页签重绑）。

**2）全站表格列压缩（系统性排查）**

写脚本扫描 15 个页面所有滚动容器，找出 7 处列数超出容器的表格，通过「合并相关列 + 收窄编号/时间列」压缩：

| 表格 | 溢出 | 处理 |
|---|---|---|
| 风险事件列表 | 369px → 0 | 11 列 → 8 列（类型+规模、区域+高度+趋势、保护对象+距离合并），面板比例 1.1/1.3 → 0.95/1.5 |
| 设备管理 | 327px → 0 | 12 列 → 9 列（类型+通道、产权+位置、型号+供应商合并） |
| 告警列表 | 300px → 0 | 9 列 → 7 列（类别+类型、目标+区域合并） |
| 飞行计划 | 280px → 0 | 12 列 → 9 列（无人机+机型、单位+飞手、用途+区域合并） |
| 处罚案件 | 249px → 0 | 12 列 → 9 列（机型+主体、时间+区域合并） |
| 设备实时告警 | 221px → 0 | 设备名与告警内容并入一格上下排 |
| 区域分布 / 判定结果 | 131 / 93px → 0 | 收窄数值列、时间只显示时分秒 |

**3）修掉一个图表渲染时序缺陷**

环图（`CH.donut`）按容器宽度决定图例位置（窄容器图例移到底部）。页签切换时容器尚未完成布局，`clientWidth` 为 0 触发兜底值 300 → 误判为窄容器，图例被塞到底部并分页。已改为**延迟一帧待容器完成布局后再初始化**，并在两个页签页面加同样的 `requestAnimationFrame` 保护。

**4）归档趋势图双 Y 轴**

归档总数（约 2,300）与异常日志数（约 70）量级相差 30 倍，同轴显示时异常线贴底不可见。改为双 Y 轴 + `yScale`。

> 注：综合态势总览的三个通道环形图（74px）、合法性判定的评分环（76px）、设备监测的资源迷你图（44–58px）为刻意设计的小尺寸图元，不属于错配。

## 三·九、第六轮：融合感知中心布局重构

### 问题

页面拥挤，实测：底部区域固定 271px，但「多源融合识别结果」内容需要 308px —— **超出 37px 被直接裁掉**，雷达—光电关联行（F0209）显示不全；右栏告警列表内容 695px 挤在 420px 行内，只能看 2 条；处置流程步骤条底部被切。

根因是三段式布局（工具条 / 地图+右栏 / 融合+处置）把纵向空间切碎，每段都不够用。

### 重构

**布局改为左右两大栏**（主区吃掉除工具条外的全部高度）：

```
工具条（单行筛选）
├─ 左栏 flex:1 ─────────────┬─ 右栏 420px ──────────┐
│  地图（flex:1）            │  当前追踪目标·处置·流程 │
│  多源融合识别结果（346px）  │  实时告警列表（flex:1） │
└───────────────────────────┴───────────────────────┘
```

具体调整：

1. **图层控制移入地图右上角浮层** —— 工具条从 81px 降到单行，且符合 GIS 系统惯例
2. **图层与图例合并为一个浮层** —— 原先地图上两个框都列了「禁飞区/适飞空域/限高管制」，属重复；现在每个图层开关自带线型色块，轨迹图层下缩进显示合法/非法/弥合段(A03)/预测段(A04)四种线型
3. **处置动作与处置流程并入「当前追踪目标」面板** —— 三者本就针对同一目标，省下两个面板标题栏与间距（约 52px），且反制按钮无需滚动即可见
4. **目标信息改双列紧凑排布** —— 去掉信息量低的 88×66 大图标，基本参数两列显示（约 230px → 130px）
5. **融合卡行距与关联行紧凑化** —— 卡片行高 22px → 18px，B 档合规标注并入标签（hover 显示完整说明）

### 结果

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 融合识别区 | 内容 332px / 可见 262px，**裁切 70px** | 内容 296px / 可见 296px，**零裁切** |
| 雷达—光电关联行 | 被裁切 | 完整可见 |
| 目标与处置面板 | 内容 459px / 可见 356px，裁切 103px | 471 / 471，**零裁切**，反制按钮免滚动可见 |
| 实时告警列表 | 1–2 条 | 2 条（面板 107px → 145px） |
| 地图 | 420px | 344px（换取下方内容完整） |

## 五、正式接口如何替换（纪要 §12 替换机制）

Demo 数据全部收敛在 `assets/js/mock.js`，页面只消费它导出的对象：

```js
MOCK.devices / deviceStats     ← 设备协议、心跳、状态
MOCK.allTargets / liveTargets  ← 融合感知箱 / TDOA / 5G-A 三路目标
MOCK.airspaces                 ← /api/v1/airspace/query
MOCK.flightPlans               ← /api/v1/flight/plan/list
MOCK.alarms / cases / authLogs ← 告警、案件、反制与干扰授权
MOCK.interfaces / ifStats      ← 接口总表
MOCK.logs / logStats           ← 日志归档
```

正式接口到位后，**只需把 `mock.js` 换成真实 Adapter（保持同名导出与同一 Schema），页面与业务逻辑不动**。
