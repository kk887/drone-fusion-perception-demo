## 分工：按业务链条切，不按页面数量切

**为什么这么切**：需要一起改的页面必须落在同一个人手里。
风险和航线要互相看得见；告警→判定→处罚→证据是一条案件流水线。
**切错的话，一个跨页需求会变成两个人对着改，那就是冲突的来源。**

## 三个「公共件」：谁改都要先说

```
assets/js/mock.js      数据层     3700 行   16 个页面全依赖
assets/js/ui.js        公共组件    270 行   面板/表格/弹窗/分页
assets/css/app.css     全局样式    600 行   全站排版
```

**这三个文件改动前必须在群里说一声。别的文件随便改。**

这条不是形式主义，是有代价的教训：

> 有人把表格字号从 12.5px 调到 13.5px，**七个页面同时出现横向滚动条**。
> 发现的人不知道是谁改的、改了什么，花了两轮才定位到。
> 而且同一次改动里还装着侧边栏加宽——**两件事被当成一件**，
> 导致第一次因果验证只还原了一半，结论也就错了一半。

### 数据层改动要排队，不要并行

两条链都会需要改底层（A 要给空域加"来源"字段，B 要给证据加溯源字段）。
**底层只有一份，两个人同时写必撞。**

做法：**各自把需要的字段列出来 → 一个人一次性加完 → 两人再动页面。**
底层改动通常不到两小时，排队比并行快。

## 页面之间通信：走数据层，不要直接互调

比如「从告警页点进处罚页并选中那条」——
不要让告警页去改处罚页的变量，用现成的跨页上下文机制（`U.goto` / `U.consume`）。

**优先级是固定的：`U.consume` 上下文 > 演示主角 > 列表第一条。**
从别处跳进来时，选中的必须是点的那条，不能被默认值覆盖。

## 提交前必须跑的三个脚本

```bash
cd dongying-demo
node -e "global.window={};require('./assets/js/mock.js');
         const c=window.MOCK.selfCheck();
         console.log(c.filter(x=>x.ok).length+'/'+c.length);
         c.filter(x=>!x.ok).forEach(x=>console.log('FAIL:',x.name,'|',x.got))"
node tools/scan.js       # 源码合规扫描
node tools/falsify.js    # 断言证伪
```

**三个跑绿再提交。** 能挡掉大部分「我这好好的怎么到你那就坏了」。

浏览器侧还要看：**16 页 0 报错 / 0 横向溢出 / 0 静默裁切**，
测量宽度固定 **1440×900 与 1600×950 两档**。

> ⚠️ 量溢出前先确认 `innerWidth >= 1200`。
> 浏览器面板缩小时量出来的数字全是假的——这个坑我们踩过两次。

## 几条踩过的坑，别再踩

**语法检查通过 ≠ 能跑。**
`node --check` 查不出未定义函数，也查不出 TDZ（`const` 声明在使用点之后）。
数据层因此白屏过一次，表现为**六个没动过的文件同时报 `MOCK is not defined`**。
> **多个没动过的文件同时报错 → 往共同依赖的上游查**，不要逐个查报错文件。

**定位样式回归靠逐项还原，不靠改动记录。**
同一次改动里可能装着好几件事。
正确做法：注入 CSS 把可疑变更**逐项**还原，看哪一项让数字归零。

**兜底不能替换成另一个实体。**
`find(...) || 列表[0]` 这种写法：查不到就落到第一条，
界面上会显示一个**看起来正常但完全无关**的东西。
兜底可以降级为「显示不了」，不可以冒充。
（默认选中这类**用户看得见、可改**的除外，写 `// safe-default: 理由`。）

**断言要能失败。**
新加的自检断言必须在 `tools/falsify.js` 里配一条注入，确认它**会变红**。
两端同源的断言（拿自己算出来的数跟自己比）永远绿，占着「已验证」的名额。
