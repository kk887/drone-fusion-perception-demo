# tools/ —— 验证工具

五个脚本，纯 Node 内置模块（`dewatermark.js` 例外，需 `sharp`）。仓库无 `package.json`。

```bash
node tools/scan.js          # 源码级合规扫描      退出码 0=通过
node tools/falsify.js       # 断言证伪            退出码 0=必抓注入全被捕获
node tools/overflow.js      # 横向溢出探针（生成器，贴进浏览器 console 跑）
node tools/tilecheck.js     # 本地瓦片完整性
node tools/dewatermark.js   # 离线去瓦片水印（--dry 预演）
```

当前状态：`scan` 7 条硬性规则 + 1 条待办；`falsify` 133 条断言 × 115 种注入，必抓注入全部捕获；`overflow` 两档宽度 **17 页** A=0 B=0；`tilecheck` 无缺失。

> 页数从 16 变 17 是因为新增了「目标事件工作台」（`pages/workbench.js`）。
> `overflow.js` 逐页体检遍历的是 `window.PAGES`，加页不需要改工具，但这行状态数字要跟着改 ——
> 否则下次看到 17 会以为是工具跑串了。

## 为什么要有这份 README

这些教训原本散在各个文件的头注释里，而**它们是同一族**：读到其中一个文件的人看不见另外几个的失效史，于是同一个坑被换个地方重踩。下面按"一条判据是怎么失效的"归类，不是按工具归类。

> **会漂的是数字，不漂的是关系。文档要记住的是后者。**

这句是这份文档存在的理由，也是它的写法约束。一次自查证实了它：当初记的三组对账数字 26↔26 / 51↔51 / 91↔91，如今是 18↔18 / 54↔54 / 97↔97 —— **数字全变，关系一条没塌**。所以下文尽量写关系、写形状、写判据，具体数值只在"当时的实测"这个意义上出现，并标明它会过期（见文末《这份文档本身要定期自查》）。

## 一条铁律：工具坏掉时的表现是"全绿"

**这与真的没问题在结果上完全一样。** 所以任何"没发现问题"的报告，都必须先回答一个问题：**这个工具此刻还能发现问题吗？**

做法是**出数前先注入一个已知的真阳性**，抓到了才允许打印结果：

- `falsify.js` 整个工具就是这条纪律的实现——对数据层施加 115 种定向注入，记录每条断言是否至少被弄红过。**从未被任何注入弄红的断言会被单独列出**：恒真的断言价值为零，而且比没有更糟，它占着"已验证"的名额。
- `overflow.js` 的探针在扫描前注入一个必然溢出的 `hidden` 盒和一个 `auto` 盒，**两档各抓到一个才出数**，否则 `console.error` 并拒绝打印任何页面结果。
- 新增 scan 规则时同样适用：本仓库那条兜底规则上线前，用临时文件验过三档——无声明的能抓到、写了 `safe-default:` 的不报、降级为 `null` 的不报。

**注入必须覆盖工具声称能查的每一类**，只验证其中一类不足以说明其余几类有效。（`overflow.js` 的探针自己就栽在这里：它只验了 A 类，而 B 类的豁免逻辑是错的。）

## 判据失效史：五种形态

### ① 拿标记当事实——类名不等于滚动容器

`overflow.js` v1 查 `.scroll` 类名，而 `app.css` 里 `.pb` 有 `overflow:auto` 却没有这个类。**九次复现全部落空，真正溢出的元素一次都没进过查询结果。**

### ② 在不会发生该现象的对象上测量它

v2 改查 computed `overflow-x`，但仍在 **`overflow:visible` 的元素**上量 `scrollWidth`。visible 元素越界只是"画到自己盒外"，**裁切只发生在最近的非 visible 祖先上**。风险页那 4~5px 就是这么误报的：内容画到 x=1395，而最近的裁切祖先右边界 1414——一个字都没少。

### ③ 豁免过宽，把要查的东西整类删掉

v3 加了 ellipsis / 可滚动豁免，结果把 `auto`/`scroll` 整档豁免了——**等于把"出现横向滚动条"这类缺陷从体检里删掉，而那正是当初要治的东西**。现在分两档：A 静默裁切（hidden/clip 且越界，用户无从看到）、B 横向滚动条（auto/scroll 且真能滚，内容可达但布局已破）。

### ④ 比对的两端来自同一处

- `mock.js` 曾有断言拿存储值和 `riskLevelOf()` 比，**而存储值就是 `riskLevelOf()` 产出的**——把实现退回错版本，断言照样通过。
- 同族：`tilecheck.js` 的头注释写明地图范围 `B` **从 `map.js` 实际解析**而不是抄一份。抄一份的话，`map.js` 改了边界这里不会跟随（本轮真的发生过：边界对齐后按旧值仍报 35,570 张缺失）。
- 同族：验证 `overflow.js` 时不另抄一份探针，而是让浏览器 `fetch('/tools/overflow.js')` 把原文抠出来 `eval`。**只要"被验的东西"和"跑的东西"之间隔了一次人工搬运，验证就失去意义**——手抄、复述、"我改的就是这个"都算搬运。

### ⑤ 判据太宽等于没有判据

排查"读了没人维护的字段"时，第一版抽出所有 `.字段` 记号与数据层字段并集比对，结果满屏 `getElementById` / `fillStyle` / `st.astatus`——页面局部状态与 DOM 成员把信号淹没，真阳性 0 个。

第二版**按危害形状查，而不是按名字查**：那个 bug 的害处从来不在"字段没了"，在"读不到时会拿另一个真实对象顶上"。于是 grep `find(...) || 集合[下标]`，一次命中全部同族。**前者是原因，后者才是可被搜索的特征。**

## 规则的写法

### 注释行不是代码

规则若把说明文字也算违规，就会**逼人把教训从注释里删掉**——而那正好把知识删没了。`scan.js` 默认跳过注释行，需要连注释一起查的规则显式声明 `alsoComments: true`。ADS-B 那条被这么误伤过一次。

### 豁免要声明，不要自动匹配

自动豁免会成为新的漏洞；声明式豁免留下一条可审查的记录。兜底那条规则的做法是：**不判断语义，只强制那个判断被写下来**——命中形状的行必须在本行或上一行写 `// safe-default: 理由`，没写的才报。

### 新规则先进 `todo` 档

一条新规则若一上来就把全站判红，等于替别人的文件做了判断，**而且会逼人为了消红随手加一句敷衍的豁免注释——机制还在，作用没了**。`rule.todo = true` 让它显示为"待办"且不影响退出码；各属主标注或改完后去掉 `todo` 即转硬性违规。

> 一个正确的机制，可以被它的引入方式毁掉。

### 一条绿着的规则也可能是错的

`scan.js` 有一条「不得出现 ADS-B」，依据是"三份协议枚举里没有"。但真实设备清单里**确实有** ADS-B（UAVIONIX pingstation3），当初据以删除的前提已被推翻。**这条规则现在会拦住正确的修复**，而报红的东西天然显得是"违规"。

**红的有人查，绿的没人看。** 常绿规则从不产生信号，因此永远不会被审视，直到有人试图做正确的事被它拦住。该条已知错误但**故意留着**——它错得可见，删了反而没人记得这里曾有过约束；待客户拍板后连同其余几条一起改。

## 覆盖边界：这些工具查不到什么

**把"这次没覆盖什么"写进输出本身**，下一个人就不用重新踩一遍，也不会误把"全绿"当成"全都测过"。

- **字段改名/删除后页面渲染出 `undefined`** —— 三道关全绿也照样发生过。`selfCheck` 查数据自洽（数据确实自洽）、`scan` 查源码模式（字段名没写错，是字段没了）、报错监听查抛异常（`undefined` 进模板字符串是合法字符串，不是异常）。补法是扫渲染结果里有没有 `undefined` / `[object Object]` / `NaN`——**它不需要知道字段叫什么**，而现有三道关全是"知道要查什么才查得到"。
- **兜底值造成的错值** 比 `undefined` 更隐蔽：`undefined` 至少在页面上留了字样，兜底是把"字段没了"变成"字段有个错值"，类型对、格式正常，只是讲的是另一个实体的事。
- **窗口缩放后的重排** —— `overflow.js` 只覆盖"导航后的静态渲染态"。浏览器面板隐藏时 `document.hidden=true`，**ResizeObserver 与 rAF 一次都不触发**（实测 RO 回调数为 0，连 observe 后本该有的首次回调都没有），依赖它们重绘的图表跑不起来，读数全是环境假象。该路径必须在可见窗口里手动拖一次。探针会读 `document.hidden` 并在结果里标注这条边界。
- **页面硬编码的数字** —— `falsify.js` 改数据层数组长度时，若页面把数字写死，本层查不出，归 `scan.js` 的源码规则管。
- **加载期求值的常量** —— 曾有 `const ME = users.find(...)` 在模块加载时只算一次，运行期改数据不重算，因此**运行期构造不出它的兜底路径**。测不到它，恰恰是因为它以不该有的方式被钉死了：**测试困难本身是设计的一个信号**。改成运行期读之后，那处立刻就能测了。

## 测量前先确认：这个环境回答的是不是你要问的那个问题

一次测量可以**结果完全真实、却答非所问**。这比测错更难发现，因为数字经得起复核。

`overflow.js` 曾在浏览器面板折叠时（`innerWidth === 0`）吐出一份"16 页全是溢出"的清单——格式正常、数字具体。**探针有真阳性自检，却从没检查过视口本身值不值得测量。**

补守卫时又发现一层：面板有最小宽度，请求 300px 实际得到 1200px，而**1200 下的溢出是真的**——这套布局本来就排不下。所以守卫不能写成"视口荒谬则拒测"，得写成**"低于设计基准则拒测"**：

> 低于基准时溢出确实存在，但它回答的是"这套布局支不支持 1200 宽"，**不是**"页面有没有裁切缺陷"。**把后者的答案填进前者的报告，就是一次问错问题。**

同族的历次翻车都是这个形状：用瓦片包的 bbox 回答覆盖完整度、用页面级溢出回答容器级裁切、用设备当前指标回答几天前那次调测是否达标。**共同点是那个观察本身没错，错的是它被拿去回答了另一个问题。**

### 除了"问错环境"，还有"问错层"

同一个问题——**这套布局的最小宽度是多少**——在两个层上问，得到两个都"算得出来"的数：

| 问哪一层 | 做法 | 答案 | 对不对 |
|---|---|---|---|
| 源码层 | 读 `app.css` 的 `min-width` 声明相加：侧栏 170 + 主区 1180 | **1350** | 错。那条 1180 被后面一条同选择器规则覆盖，从未生效 |
| 渲染层 | 逐页量 `body{width:min-content}` | **1441** | 对 |

差 91px，而且**结论相反**：按 1350 算，1366 的笔记本"余量 16px、勉强够"；按 1441 算，**16 页里有 10 页会出横向滚动条**。

两个数都看起来算得出来，这正是它难防的地方。**在有层叠、有覆盖、有派生的系统里，源码不是事实，渲染结果才是**——声明值是"作者以为的约束"，computed 才是实际生效的约束。同理：`selfCheck` 的断言值不等于页面显示的值，数据层的字段名不等于页面读到的字段。

现在 `overflow.js` 里 `BASE_W = 1440`，不达基准直接返回「视口低于基准 1440px（当前 1200px）」并说明拒绝理由，而不是给一份看起来正常的清单。

### 顺带实测出来的：这套布局的真实地板

从 CSS 推算会得到错的数。`app.css` 里 `.main` 有**两条**规则——第 55 行 `min-width:1180px`、第 78 行 `min-width:0`，同特异性后者胜，**computed 值实测是 `0px`**。所以"侧栏 170 + 主区 1180 = 1350"这个算法不成立。

真实地板是**每页的 min-content 宽度**，逐页不同。测法：

```js
document.body.style.width = 'min-content';
Math.round(document.body.getBoundingClientRect().width);
document.body.style.width = '';
```

**全站地板 ≈ 1441px（最大值出现在 stats / monitor）；16 页里 13 页超过 1280，10 页超过 1366。** `header.hdr` 那条 `min-width:1280px` 只管住了顶栏，管不住内容。

> ⚠️ **逐页的具体数值不写在这里** —— 它们随页面内容和样式漂移。一次自查发现十个数里有七个已经和当初不符（`users` 1429→1440、`archive` 1280→1296、`evidence` 1345→1361 …）。**结论（全站地板、1366 会有多少页超标）比逐页数值稳定得多，要用数值就当场量。**

也就是说：**1366 的笔记本上，十个页面会出横向滚动条**——而横向滚动条正是本项目已经判定为缺陷（B 档）、用户也明确说过难用的那个东西。低于地板时页面不会"看起来坏掉"，它会**以我们已经判定为缺陷的那种方式退化**，这比排不下更麻烦，因为它看起来像还能用。

最小支持宽度**从未定义过**。在定下来之前 `BASE_W` 保持 1440：现在这份"1440/1600 无裁切缺陷"的报告是真的、也是有用的；为覆盖 1366 而降基准，只会得到一份混着"布局地板问题"和"裁切缺陷"的清单——正是上面那条守卫要挡的东西。要测 1366 就**另开一档单独测、单独报，两类结论不合并**。

## 判据缺席不等于谨慎

有一版调测报告的原则写着「通过/不通过取自记录自身的 `result`，不自造阈值」，理由是阈值本来就"待设备方确认"。

看似谨慎，实际是**从结论去挑指标**：报告先知道这次算成功还是失败，再把指标摆成配得上该结论的样子——**一份永远自洽、也永远证明不了任何事的报告。**

> **「值待确认」和「不许有判据」是两回事，后者会让报告失去可证伪性。**

纪要 §7 禁止的是**编造数值**，不是禁止**存在判据**。正确做法是：给出 Demo 缺省阈值并**标明它待确认**，由它推导结论；把记录里原有的 `result` 降级为**交叉探针**，两者不一致时显式报 mismatch，而不是让某一方悄悄赢。

## 观测记录只能由业务事实生成，不能由界面动作生成

处罚页从本地缓存**还原**上次会话的复核结果时，一度想直接调数据层的 `setCaseStage()` —— 那个函数会写 `restageLog` 与审计日志。后果是：**每刷新一次页面就多一条"案件回退"审计记录，而现实中什么都没发生。**

那份审计记录的就不再是"发生过什么"，而是"页面被打开过几次"。

> **审计记录不得由界面动作生成，只能由业务事实生成。**

这是「结论不得反向生成观测事实」的镜像。判据是问一句：**这一步在现实世界里对应一个动作吗？**
- 用户点「撤销案件」→ 是，写审计
- 页面重建自己的显示状态 → 否，只重建，不写

同族的还有：重新渲染不算一次"查看"（否则访问次数会随重绘增长）、轮询拉取不算一次"操作"、失败重试不算多次业务请求。**共同点是把"程序做了几次"错记成了"人做了几件事"，而这类错误会让台账在事后看起来完全合理。**

更要命的是它的方向：**这类错误永远是多记、不是少记**。于是它不会触发"数据缺失"那类告警，只会让所有统计缓慢偏高 —— **没有一条断言会因为数字变大而失败**。要抓它，断言就不能只写"台账非空""字段齐全"，得写成**与现实动作数对得上**：几次点击、几次审批、几条记录，三者必须同源。

## 台账断言要双向逐条映射，不能只对总数

`every()` 检查集合里每个元素是否合格，**但对这个集合该不该这么大完全无话可说**。守恒等式（总数 = 分项和）能防多，可它只用在统计口径上——而**台账才是"多一条就是错"的数据结构**，偏偏一条守恒约束都没有。

一次追加型台账普查（只查"多一条即为错"的集合）验证了这个盲区，并查出一处真实缺陷。**下面是修复前的实测（现已修复为 18/18/0，此处保留是为了说明缺陷的形状）**：

```
走过「反制处置」环节（stage>3）的案件   62
其中有授权记录（authLogs）的            24
无任何授权记录                          38   ← 61%
另有 2 条授权记录属于尚未走到该环节的案件
```

纪要 §6.3 是「反制人在回路 / 需请示上级主管部门」，所以这不是"少了几条记录"，而是：**`stage>3` 断言了"反制已完成"，而系统里没有任何事实支撑它——做了什么、谁批的、用哪台设备，一概没有。**又一次「结论没有来源」，只是这次的结论叫"已实施反制"。

关键在于它**双向都错**：38 条缺失 + 2 条孤儿。所以断言必须写成两条，且必须同时立住：

```
① 每个走过该环节的案件都有对应授权记录   ← 防漏（抓 38 条缺失）
② 每条授权记录都对应确实走到该环节的案件 ← 防孤儿（抓 2 条）
```

**只写①，2 条孤儿照样通过；只写②，38 条缺失照样通过。** 任何单向断言在这次的缺陷面前都会给出"全绿"。

也不能退化成对总数：**计数相等可能只是"漏 38 补 38"的巧合，逐条双向映射不会。**

### 对账端必须独立

右端不能从台账自己派生，否则又是那条老规矩：**两端同源则恒真**。授权记录要对的是"有多少案件走到了需要授权的环节"，不是"authLogs 里有多少条"。

普查中能找到独立对账端的四处（现状均已对上，因此**都必须配注入才有意义**）：

```
证据·系统反制授权引擎  ↔  authLogs（授权号全覆盖，0 孤儿）
证据·处罚文书          ↔  已结案案件
riskNotices            ↔  状态≥已通知的风险事件（双向 0 差异）
restageLog             ↔  复核撤销/重判次数
```

**这里刻意只写关系、不写数字。** 一次自查证实了原因：当初记的是 26↔26 / 51↔51 / 91↔91，如今是 18↔18 / 54↔54 / 97↔97 —— **三组数字全变了，三组关系一个没塌**。

> **会漂的是数字，不漂的是关系。文档要记住的是后者。**

### 找不到独立对账端本身就是发现，不要硬凑

`ruleVersions`：版本发布是人的动作，系统里没有第二处记录"发布过几次"——多一条、少一条、改一条，全站无感。

`auditLogs`：更彻底。它是所有模块动作的汇总，而"一共做了多少动作"这个量不存在于任何地方。

想过"让每个写审计的动作同时递增一个独立计数器"，结论是**不做**：那个计数器同样没有第三方能对，只是把"无法证伪"推后一层。**接受"结构性无法对账"并写明理由，比一个看起来能对账的假机制诚实。**

### 错误的方向不是只有一个

上一节说"这类错误永远是多记不是少记"——**那只对统计口径成立，审计台账正好相反**：

> **多写只是噪音，漏写是掩盖。**

所以两者要用不同方向的断言防：统计口径防多（守恒等式），审计台账防漏（逐条映射）。**用错方向的断言会一直绿着**，而它守的那一侧从来没有出过问题。

## 在自己定义域内完备的实验，看起来和真正完备的实验一模一样

它不会给你任何"还有东西没测"的信号 —— 因为在它的范围内，确实什么都没漏。

一天之内这个形状出现了四次，每次都是**我们自己划的圈，而且都没意识到在划**：

| 划圈的东西 | 圈住了什么 | 后果 |
|---|---|---|
| 概括词「外壳」 | 还原候选只取了 `nav` / `view padding` | 同一次改动里的 `table.tb` 排版自动出局，因果只解释到 34px |
| 文件位置「416–424 这一段」 | 扫描候选只取了连续那一段 | 漏掉 592–594 的三条同类规则，把"局部还活着"误判成"整体空壳" |
| 维度「penalty 和 violation」 | 只查了两个维度 | 得出"没有任何维度能解释这个切分"，而**日期**解释得很干净 |
| 语义「静默失效的 CSS」 | 只找值被覆盖的 | 漏掉值相同的覆盖 —— 它记录的是一个**已经不存在的差异** |

### 三条可操作的判据

**① 还原候选按改动的物理范围取，不按语义范围取。**
定位样式回归时，用"注入还原候选、逐项验证"比按 mtime 推断因果可靠得多。但**还原哪些东西，要按"这次改动物理上动了哪些行"来定，不按"它们算不算同一类"**。一次改动里可以装着好几件互不相干的事 —— 这次就装了两件（外壳宽度 + 表格排版），而我们从头到尾用一个词指代它，于是只还原了一半。

**② 扫描范围同理：按符号取，不按位置取。**
`grep 'body.bigscreen'` 会给出全部 12 条；读"那一段"只会给出 9 条。

**③ 全称结论必须配全称检查。**
凡是"我检查了 X、Y、Z 都不成立"，结论只能写成「**X/Y/Z 不解释**」，不能写成「**没有东西解释**」。后者需要的是穷举，而穷举很少真的做过。

## 测量还需要一个稳定的环境，不只是一个合适的环境

上一节说的是"这个环境回答的是不是你要问的问题"。还有一条更基本的：**被测的东西在两次测量之间不能变。**

两个会话按同一方法查同一件事，得到相反的结果：

```
一份：无授权 38 / 有授权 24，日期边界干净，0 天重叠
另一份：无授权 44 / 有授权 18，11 天既有又无，无边界
```

**都不是算错。**随机性已排除（种子硬编码，同一份文件跑三次完全一致）——是 `mock.js` 在两次测量之间被改了，`authLogs` 从 26 条变成 18 条。

**两份报告都是各自那一刻的真实属性，但都不能当结论。**而报告本身看不出这一点：数字具体、方法一致、复核也复核不出问题。

所以 `overflow.js` 现在会取 `mock.js` 的**内容指纹**并写进结果（`203841B/7337f174` 这样）。用指纹而不是 `Last-Modified`：本地静态服务器不一定发那个头（实测就没发），而**"取不到版本"和"版本没变"在报告里长得一模一样**。指纹只依赖文件内容本身，不依赖服务端配合。

> **两份报告如果基于不同版本，数字不可比 —— 这件事必须由报告自己说出来，不能靠人记得。**

## "取不到"必须落在正常值域之外

任何一个**可能取不到**的量，"取不到"必须是一个和所有正常取值都不同的状态。否则缺失会被渲染成一个具体的、看起来完全正常的值，而报告读不出区别。

同一天里这个形状出现了三次：

| 场景 | 缺失被渲染成了 | 后果 |
|---|---|---|
| 浏览器面板折叠 | `innerWidth === 0` | "没有视口"被读成"视口很窄"，16 页全报溢出 |
| 服务器不发 `Last-Modified` | 一句"(服务端未给)" | "取不到版本"与"版本没变"在报告里长得一样 |
| `text().length` 当字节数 | 203841 | 与磁盘 `wc -c` 的 269693 对不上，被误判成"取到了缓存旧副本" |

第三条是自己绊自己：**`String.length` 是 UTF-16 码元数，不是字节数** —— 中文一字 1 码元却占 3 字节，本项目 `mock.js` 是 203841 码元 / 269693 字节。两个数都真实、都可复算，只是**单位不同**。差点因此去修一个不存在的缓存 bug。

正确做法：字节数走 `arrayBuffer().byteLength`；取不到版本时返回一个显式的异常态，而不是一个能被当成指纹的字符串。

> **两个数都算得出来，不等于它们可比。** 先确认单位，再比大小 —— 这和"先确认层、再取值"是同一件事。

## 谓词写错了，数据没错

复核授权台账时，我用 `usedCounter === true` 数出"实施反制 20 件、有授权 18 件、缺 2 件"，另一份报告是 18/18/0。差异不在数据，在谓词：

```
CF20260826001  usedCounter:true  stage:1
  反制处置环节  applicable:true  t:'待处理'  done:false      ← 还没执行
```

`usedCounter` 的含义是**这起案件的流程包含反制环节**（applicable），不是**反制已经执行**。这两件还停在待核实，授权当然还没发生 —— **它们没有缺，是还没到。**

**教训不是"要看仔细"，是：在拿一个布尔字段当"某事已发生"的证据之前，先去看它对应的那条流程记录说什么。** 字段名会诱导：`usedCounter` 是过去式，读起来像"用过了"，而它实际表达的是"会用到"。**名字断言的东西可以比数据实际表达的更多**，这与本文档反复出现的"结论没有来源"是同一族，只是这次多出来的断言藏在命名里。

## 一次正确的修复，会新造恒真断言

我们一直在找**存量**的恒真断言，没想过**修复动作本身会生产新的**。

实例：`classification_confidence` 被全量置 `null`（协议里根本没这个字段，置 null 是对的）。而守它的断言长这样：

```js
targets.filter(t => t.classification_confidence !== null).every(t => …)
```

**filter 出空集，`[].every()` 恒为 true。** 修复之前它有效，修复之后它变成一条不可能失败的断言——**而它从绿变绿，没有任何时刻发出过信号。**

> **改动之后要重查它波及的断言是否变成了恒真**，尤其是带 `filter` 的：`filter` 把"没有样本"和"样本全部合格"折叠成了同一个结果。

这跟本文档反复出现的「没有样本走到那条路径」是同一族，区别在触发方式：那些是**数据天生没覆盖到**（stage=3 零件、分歧区无事件、fail-open 兜底休眠），这一条是**我们自己动手把样本清空的**。后者更值得防，因为**动手的人当时正在做一件正确的事**，注意力全在修复上，不会想到去看断言。

配套的一条：`filter(...).every(...)` 这个形状，最好同时断言 `filter` 的结果非空——**否则它防的是"有没有坏的"，而不是"该有的还在不在"。**

## 修法不是把两端统一，那又同源了

「两端同源则恒真」的正确解法**不是让两端共用一份实现**（那正是同源），而是**让两端用不同实现，且都必须过**。

实例：目标是否在雷达量程内，生成侧留 50m 余量、断言侧用独立实现的大圆公式严格卡 3.5km。改完当场报红一个 3.51km 的目标——**如果两端共用同一个距离函数，公式本身写错时不会有任何一端提出异议。**

## 报断言失败要贴 `{name, exp, got}` 三元组

`MOCK.selfCheck()` 返回的对象**只有四个键**：`name` / `ok` / `exp` / `got`。**失败详情在 `got` 里**（183 条中 181 条带具体内容，其余是布尔或计数型，本来就只有数字有意义）：

```json
{"name":"空域类违规必须指得出是哪一块空域…",
 "ok":false,
 "exp":"220 条均可追溯",
 "got":"1 条对不上：UAV20260728016 的「侵入禁飞区」找不到对应的空域命中记录"}
```

我曾三次向数据层会话报"这些断言没带失败详情，建议补上编号"，三次都是**我取的键名不对**（试了 `msg` / `detail` / `why`，全是 `undefined`）。对方三次都以为是自己漏写、去补了详情。**三轮往返，起因是没人查过这个对象长什么样。**

> **贴完整对象，不要贴自己解读出来的字段。**
> 报告里写 `got` 的原文，比写"没带详情"或"某条失败"都便宜 —— 前者对方一眼能定位，后者双方都要再查一轮。

这与本文档的另一条同源（**先查签名，别传自己以为存在的参数**）：一个是给出去的键名猜错，一个是传进去的参数猜错，**都是把"我以为的接口"当成了接口**。

## 共用工作区里，文件中间态会被别人读到

同一形状在一天内出现三次，每次都是我在对方多步编辑的中途取了数：

```
① mock.js 删 protectZones 到一半  → 全站白屏，我报"紧急"
② 数据层修复中途              → selfCheck 175/3，我报"3 条失败"
③ 加断言→报红→修根因→转绿      → selfCheck 183/1，我报"1 条失败"
```

**三次的读数都是真的，三次都不是最终状态。**对方的纪律是"多步编辑期间不对外报数"，但那**挡不住别人主动取**。

约定：数据层多步编辑期间创建 `dongying-demo/.editing`，改完删除；**取数方在取数前看一眼**。标记在 = 读到的是中间态，报之前先问。

这条比"小心一点"可执行，因为它把责任从"记得别读"变成了"读之前有个可查的状态"。

### ⚠️ 第一版是个永远不会报警的告警

标记原本约定放在会话的 scratchpad 目录，探针用 `fetch('/scratchpad/mock.js.editing')` 取。**那个目录不在静态服务根内，请求恒 404**，于是"编辑中"永远是 `false`。

**它比没有这个检查更糟：没有检查时人知道自己没查，有一个恒假的检查时人以为查过了。**

所以现在区分三种状态，而不是两种：

```
200 → editing        404 → idle        其它/抛错 → 检查本身失效（要说出来）
```

**"检查失效"必须与"未在编辑"分开报**——否则又回到了同一个坑：缺失被渲染成一个正常值（本文档另有一节专讲这件事）。

两个方向都实测过：`touch dongying-demo/.editing` → `editing`；`rm` → `idle`。

## 多会话共用一个工作目录：三层共享状态

多个会话同时改同一个仓库时，**没有"我的分支"、没有"我的暂存区"、也没有"我的文件中间态"** —— `HEAD`、索引、工作区**三个都是共享的**。今天三层各踩了一次。

| 层 | 症状 | 纪律 |
|---|---|---|
| `HEAD` | 别人的 merge 把我未提交的 9 个文件卷进它的 `wip` 提交 | **不开分支**：`checkout -b` 会把别人脚下的分支一起切走 |
| 索引 | 只 `git add` 自己的两个文件，提交出来是五个 —— 另外三个是别人先 add 过的 | **用 `git commit -- <路径>`**，绕开索引 |
| 工作区 | `commit --` 提交的是那一刻的工作区内容 | 别人正在改你的文件时，**你会把他的半成品定死** |

`git add <具体文件>` 挡不住别人的改动 —— **`git commit` 提交的是整个索引，不是你刚 add 的那部分**。防错了位置：只控制了"往索引里放什么"，没控制"提交时索引里有什么"。

```bash
git commit -F - -- 路径A 路径B     # 参数顺序：-F 必须在 -- 之前
```

实测有效：提交时索引里躺着别人的 `workbench.js`，`git show --stat` 确认只进了我指定的 5 个文件。

**但第三层没有解决。**`commit --` 让"提交谁"可控，"提交的是什么内容"仍由共享工作区那一刻的状态决定。真正安全需要每个会话有独立工作副本（worktree）。在那之前，**能做到的上限是"不主动扩大伤害"，做不到"不被波及"**。

配套的两条：多步编辑期间别让别人以为可以读（**改完一次性验完再说** —— 一次数据层多步替换的中间态被读到，直接导致全站白屏）；改公共件前先知会属主，而且**这条规则要双向**才立得住。

## 没有时限的暂停，效果上就是否决

跨会话叫停必须附**时限**与**追问人**，超时自动放行并通知 leader。

今天有一次叫停理由是实的（删掉的模块其数据仍是判定核心），但没给时限、也没指定谁去问用户，**在被叫停方看来就是无限期阻塞** —— 而用户其实已经明确指示过两次、还催过一次。**理由成立不等于形式正确：一个没有出口的暂停，和否决无法区分。**

## 删页面 ≠ 删数据，边界必须有人明确划一次

`airspace` 页面被清理后：入口没了，`M.airspaces`（8 条）仍被 8 个页面引用、220 个目标的判定要件仍触及空域。

**这两件事的边界不划清，就会出现"以为删干净了，其实判定还在跑"。**

由此派生一条可操作的：**页面没了不等于参数没了。参数的去留看判据还在不在，不是那个页面还在不在。**该页注册的两组参数因此是迁移而非删除 —— 走廊宽度仍被偏离判定读取，冲突检测阈值仍被数据层断言使用。留一条指向不存在页面的参数记录，和删掉它一样错。

同族：检索类目也不能只删页面留类目 —— **一个点了没落点的类目，比没有这个类目更糟**。

## 谁说了算，`git` 补不上

`ListAgents` 只给名字，不给角色。今天为"这批改动是谁做的"问了四个会话全答不是，**因为真正在做的那个不在被问的名单里**。

> **git 补上了"谁改了什么"，补不上"谁说了算"。**

所以 leader 身份要写在文档里，会话交替时更新：原统筹会话退出后，现任 leader 是用户直连会话；新会话找不到 leader 时先问它。

## 这份文档本身要定期自查

一条写进注释或文档的**错误诊断，比错误本身活得久** —— 错误会被修掉，注释不会。而且它会以最强的形式存在：**看起来像是别人踩过坑之后留下的忠告，谁都不会去复核它。**

这不是假想。写 `overflow.js` 的版本指纹时，我把 `text().length`（UTF-16 码元数）当字节数，与磁盘 `wc -c` 对不上，据此判定"同步 XHR 吃了缓存"，并已经把「一个会过期的版本戳比没有版本戳更糟」写进了注释。**那个缓存 bug 从来没发生过。**注释在错误被证伪之前就已经写好了，如果不是随后又量了一次 `arrayBuffer().byteLength`，它会一直挂在那里，还挺像回事。

### 自查规程

**每一条"教训"，能不能指回一次真实发生过、可复现的失败？** 指不回去的，要么补上证据，要么删掉。

一次实际执行的结果（27 节）：

| 类别 | 结果 |
|---|---|
| 源码类断言（机制是否真的在文件里） | 11 条全部属实 |
| 逐页 min-content 数值 | **10 个里 7 个已过期** → 改为只留结论与测法 |
| 台账对账数字（26↔26 等三组） | **数字全变，关系全在** → 改为只写关系 |
| 缺陷现状描述（授权 62/24/38） | 已修复 → 标注"修复前"，否则读者会当成活缺陷 |

**三类过期方式各不相同，但都不会自己暴露**：数值悄悄漂、缺陷已被修好、诊断从来就是错的。所以自查要分别问三个问题：**这个数现在还是这个数吗？这个问题还在吗？这件事真的发生过吗？**

## 空结果必须区分两种

「检查过、没有」和「没能检查」在界面上长得一模一样，但含义相反。

**错的保证比不检测更糟**：不检测时人知道自己不知道；错的保证会让人停止查证，**而注意力一旦被消耗就不会回来**。

空域冲突检测就踩过：认不出行政区时兜底到第一个区，于是拿另一个区的范围去跑检测，得出的"未检测到冲突"是对着错误位置算的。现在没有有效范围就明写「无法进行冲突检测——这里的空白不代表没有冲突」。
